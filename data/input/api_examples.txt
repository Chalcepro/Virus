# Common API Examples and Usage Patterns

### User Resource
GET /api/v1/users
- Description: List all users
- Parameters: page (int), limit (int), sort (string)
- Response: 200 OK
{
  "data": [
    {"id": 1, "name": "Alice", "email": "alice@example.com", "created_at": "2025-01-01T00:00:00Z"},
    {"id": 2, "name": "Bob", "email": "bob@example.com", "created_at": "2025-01-02T00:00:00Z"}
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 100,
    "pages": 10
  }
}

GET /api/v1/users/{id}
- Description: Get user by ID
- Parameters: id (string, required)
- Response: 200 OK
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com",
  "created_at": "2025-01-01T00:00:00Z"
}

PATCH /api/v1/users/{id}
- Description: Partially update user
- Parameters: id (string, required)
- Request Body: One or more fields to update
- Response: 200 OK

## Error Handling Responses

401 Unauthorized
{
  "error": {
    "code": "AUTHENTICATION_REQUIRED",
    "message": "Missing or invalid authentication token"
  }
}

404 Not Found
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Resource not found"
  }
}

500 Internal Server Error
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "An internal server error occurred"
  }
}
